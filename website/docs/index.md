# Forget React. Forget Vue. Forget Svelte.

Use HTML, CSS, and JavaScript like you did in the old days, with the next generation of HTML.

HTMLKit brings components, routing, and server rendering to the languages you already know.

![](/htmlkit-lockup.svg)

[Get started](getting-started.md) [Explore the source](https://github.com/threadlabs-studio/htmlkit)

## Write HTML. Style it with CSS.

Your pages are `.html` files. Components declare their props and state in HTML. Write their styles in CSS and add behavior with JavaScript or TypeScript.

## Give every page a home.

A folder of pages becomes your routes. Share layouts, load data, and add API endpoints when your application needs them. HTMLKit handles development, builds, and delivery.

## Build for the browser and the server.

Prerender pages for a static host, or render them on each request. HTML Next connects the page's components and browser behavior. Choose [how to deploy](deployment.md) for your application.

## Built on the next generation of HTML.

HTMLKit uses [HTML Next](https://nextwebwg.org/html-next/), the implementation of the Next Web Working Group's [declarative components proposal](https://nextwebwg.org/declarative-components/). These proposed capabilities are available through its runtime today.

## From Threadlabs, alongside Markupress.

[Markupress](https://threadlabs-studio.github.io/markupress/) builds documentation on HTMLKit. It powers this site, too. HTMLKit handles the application; Markupress handles Markdown, navigation, and documentation versions.

## Bring your existing HTMLKit project.

HTMLKit now lives at Threadlabs as `@threadlabs/htmlkit`. The `htmlkit` commands and your page markup stay familiar. Follow the [migration guide](migration.md) to update package names and imports.

The new npm name is awaiting its first publication. The existing `@nextwebwg/htmlkit@1.0.0-alpha.69` release remains available during the transition.
